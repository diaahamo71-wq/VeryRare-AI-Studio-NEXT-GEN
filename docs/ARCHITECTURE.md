# Architecture (initial proposal)

## Goals

Build a desktop audio studio where an AI planner can translate a user's request into an explicit, inspectable workflow, invoke real tools, validate outputs, and explain what happened. Audio quality claims must be supported by measurable checks and listening tests.

## Proposed layers

1. **Desktop UI** — project browser, audio import, waveform/transport, processing graph, job progress, logs, and A/B playback.
2. **Orchestrator** — provider-independent task planner; validates plans against an allowlisted tool registry; tracks job state, cancellation, retries, and cost limits.
3. **Audio engine** — deterministic audio operations and adapters for external tools such as FFmpeg and compatible voice-conversion backends. Never silently overwrite source files.
4. **Provider adapters** — optional cloud model providers behind a common interface; keys stay local and never enter source control.
5. **Validation and review** — file integrity, duration/sample-rate/channel checks, clipping and silence checks, plus human A/B review. A model review is advisory and must not be presented as proof that the audio sounds good.

## Data flow

Import source -> inspect metadata -> ask clarifying questions when needed -> propose a plan -> show user the plan and cloud/cost implications -> execute approved steps -> validate outputs -> present A/B comparison and logs -> export to a new file.

## Safety boundaries

- The planner may only call registered tools with schema-validated arguments.
- No arbitrary shell commands generated by the model.
- Cloud upload is opt-in and clearly disclosed.
- Cancellation and timeouts are required for long-running jobs.
- Preserve originals and record processing parameters for reproducibility.
- Keep model/provider credentials out of project files and logs.

## Decisions still to validate

The desktop framework, orchestration runtime, audio backend, and packaging route will be selected after checking current support, licensing, Windows compatibility, and maintainability. This document is a proposal, not a claim that these layers are implemented.
